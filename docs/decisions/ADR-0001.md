# ADR-0001 — Supabase as application DB and Storage

- **Status:** Accepted
- **Data:** 2026-08-15

## Contexto

The VPS (2 vCPU / 8 GB RAM / 100 GB disk) is shared with other projects. Running a local PostgreSQL
or object storage would consume too many resources and compete with other workloads.

## Decisão

Use Supabase as the managed PostgreSQL database (with pgvector extension) and Supabase Storage
as the object store for all images, OCR raw output, audio files and audit exports.

## Consequências

- No local PostgreSQL container required.
- Images are not stored permanently on disk — only ephemeral temp files with TTL.
- pgvector is available via Supabase's managed Postgres.
- All buckets are private; signed URLs with short TTL for access.

## Alternativas consideradas

- Local PostgreSQL: rejected — resource contention.
- AWS S3 + RDS: rejected — additional cost and operational complexity.
- Cloudflare R2: rejected — no managed Postgres pairing.
