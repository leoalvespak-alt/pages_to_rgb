# ADR-0002 — Temporal for durable workflow orchestration

- **Status:** Accepted
- **Data:** 2026-08-15

## Contexto

Exam processing traverses 20 stages across multiple providers (OCR, LLM, TTS). Each stage can fail
and must be retried without re-running completed stages. A VPS restart must not lose progress.

## Decisão

Use Temporal Python SDK for workflow orchestration. The workflow is durable: state survives
worker crashes. Temporal Cloud is the preferred hosting target; self-hosted is fallback.

## Consequências

- `TEMPORAL_ADDRESS` and `TEMPORAL_NAMESPACE` are pure configuration — no hosting assumptions.
- Supabase DB must not be used as Temporal's internal DB.
- Activities are idempotent by design.
- Blob payloads are forbidden in activity inputs/outputs (pass storage keys instead).

## Alternativas consideradas

- Celery: rejected — no built-in durable state, limited saga support.
- Custom state machine with retries: rejected — reinventing Temporal.
- AWS Step Functions: rejected — vendor lock-in, limited Python SDK.
