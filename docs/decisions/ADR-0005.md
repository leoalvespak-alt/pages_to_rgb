# ADR-0005 — pgvector + tsvector in Postgres for RAG (no Elasticsearch)

- **Status:** Accepted
- **Data:** 2026-08-15

## Contexto

RAG requires hybrid retrieval (semantic + keyword) for Portuguese-language academic content.
The VPS cannot run Elasticsearch alongside other services.

## Decisão

Use pgvector for vector search and PostgreSQL tsvector with unaccent for full-text search,
both in the same Supabase Postgres instance. Reciprocal Rank Fusion for hybrid merging.

## Consequências

- No separate vector DB or search service required.
- Embedding dimension is migration-controlled — changing provider requires a new migration.
- HNSW index for approximate nearest neighbor when collection size justifies it.
- `KnowledgeChunk.metadata` records which embedding model/dimension was used.

## Alternativas consideradas

- Elasticsearch: rejected — resource constraints.
- Pinecone/Qdrant: rejected — additional service cost and operational overhead.
- Pure BM25: rejected — misses semantic matches on Portuguese academic text.
