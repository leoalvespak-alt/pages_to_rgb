# ADR-0007 — Explicit state machine for session lifecycle

- **Status:** Accepted
- **Data:** 2026-08-15

## Contexto

A session traverses 24 states from CREATED to COMPLETED/FAILED_FATAL/CANCELLED. Concurrent
API and workflow mutations can corrupt state without strict controls.

## Decisão

All session state changes go through a single function `transition_session()` in
`domain/state_machine.py`. Direct assignment to `session.status` is forbidden. Each transition
is validated against an explicit allowed-transitions map, persists atomically with a generated
AuditEvent, and uses pessimistic locking (SELECT FOR UPDATE).

## Consequências

- Invalid transitions raise `InvalidStateTransition` (NonRetryableError).
- Every state change has an immutable audit record.
- Structural impossibility: SolveQuestions cannot run before Gate 1 (Invariant 5).
- Structural impossibility: TTS cannot run before Gate 2 (Invariant 6).

## Alternativas consideradas

- Direct field mutation: rejected — no atomicity, no audit, race conditions.
- Event sourcing: deferred — overkill for V1, but the AuditEvent table provides replay capability.
